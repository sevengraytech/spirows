## Production Deployment

### On Production Server:

```bash
# 1. Transfer package
scp evilginx-deploy-YYYYMMDD-HHMMSS.tar.gz user@server:/tmp/

# 2. Extract and deploy
ssh user@server '
  tar -xzf /tmp/evilginx-deploy-*.tar.gz -C /var/www/html/
  cd /var/www/html/evilginx-deploy-*
  chmod +x deploy.sh
  ./deploy.sh
'
```

### What deploy.sh does:
1. Creates directories
2. Validates all files present
2. Creates `.env` from `.env.example`
3. **Auto-generates secure secrets** (UI_SECRET_KEY, UI_PASSWORD)
4. Validates required env vars (EVILGINX_DOMAIN, EVILGINX_EXTERNAL_IPV4)
5. Builds both Docker images
6. Starts services with health checks
7. Outputs login credentials

## Security Notes

⚠️ **Legal Warning:** Evilginx is a phishing framework. Only deploy in authorized security assessments on systems you own or have explicit written permission to test.

- Change default passwords
- Use strong `UI_SECRET_KEY`
- Bind UI to localhost (`127.0.0.1`) or use reverse proxy with auth
- Enable `EVILGINX_DEVELOPER=false` for production (requires valid domain/DNS)
- Monitor logs for suspicious activity
